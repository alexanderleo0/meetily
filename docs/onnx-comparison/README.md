# Сравнение GigaAM и Parakeet на Mac

Прототип отдельно от Meetily. Аудио распознаётся локально; сеть нужна для скачивания публичных весов. Запись и результаты исключены из Git.

## Запуск

Нужны `uv` и `ffmpeg`.

```sh
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python compare.py audio/meeting.m4a --output results/my-run
```

Быстрая проверка первых 90 секунд:

```sh
.venv/bin/python compare.py --seconds 90 --output results/short-run
```

Откройте `results/my-run/report.html` браузером. В отчёте есть проигрыватель, переход к фрагментам, тексты рядом и замеры. `summary.json` содержит метрики, `manifest.json` — параметры и границы общего разбиения, файлы `*.txt` — тексты с метками времени. Для нового эксперимента используйте другую папку `--output`; существующий запуск защищён от перезаписи. При прерывании остаются промежуточные `*.partial.json`.

## Методика

- Модели: Parakeet TDT 0.6B v3 и GigaAM v3 E2E RNNT, обе ONNX INT8 по умолчанию. Дополнительно `--models parakeet gigaam gigaam-ctc` и `--quantization fp32`.
- Аудио декодируется ffmpeg в mono PCM 16 кГц. Silero VAD один раз создаёт общие фрагменты: пауза 500 мс, максимум 20 секунд, padding 100 мс. Перекрытия padding на границах могут давать повторения; отдельной склейки слов пока нет.
- Каждый движок запускается последовательно в отдельном процессе. CPUExecutionProvider, четыре потока, один прогрев на первом фрагменте. Менять число потоков: `--threads 8`.
- ASR-время включает предобработку, инференс и декодирование текста. Скачивание, загрузка весов, прогрев, ffmpeg и VAD учитываются отдельно/исключены из ASR-времени. Это не полный замер нагрузки приложения.
- RTF = время ASR / длительность звука. RTF < 1 означает обработку быстрее поступления аудио. Показаны RTF по речевым фрагментам и по всей записи; второй показатель может выглядеть лучше из-за тишины.
- RSS опрашивается раз в 50 мс после загрузки/прогрева. В неё входят Python, модели и аудиобуфер; краткие пики могут быть пропущены. Это не VRAM и не пик загрузки модели.
- Временные метки относятся к фрагментам, не к словам. p95 обработки фрагмента — вычислительное время, не общая задержка появления текста: к ней добавляется ожидание конца фразы.
- Python/onnx-asr использует те же семейства моделей, но это не идентичный Rust-конвейер Meetily и не гарантия его скорости. Модели загружаются из репозиториев istupakov на Hugging Face; Meetily использует своё зеркало Parakeet.

## Оценка качества

Без ручной расшифровки нельзя честно назвать WER и победителя по точности. Прослушайте спорные фрагменты в HTML. Для расчёта WER/CER можно передать `--reference reference.txt`: сплошной вручную исправленный текст ровно того интервала, который сравнивается. Нормализация: нижний регистр, ё→е, удаление пунктуации; числа словами/цифрами не приводятся к общему виду. Поэтому нормализация чисел может влиять на WER. Имена, числа, профессиональные термины, пунктуацию и пропуски полезно оценивать отдельно.

Повторная генерация HTML из готовых JSON:

```sh
.venv/bin/python compare.py --report-only --output results/my-run
```
